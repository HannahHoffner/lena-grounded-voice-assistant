## Belegtes minimales Startprofil

Der folgende Ablauf beschreibt den geprüften Mechanismus. Er wurde im Audit aus einem separaten Git-Export ausgeführt. Ein Key ist durch die startende Person bereitzustellen; kein Beispieltoken ist funktionsfähig.

```text
docker build --pull --no-cache --target test -t lena-audit-test .
docker run --rm --network none lena-audit-test
docker build --target runtime -t lena-audit-runtime .
docker run --rm --read-only --tmpfs /tmp:rw,noexec,nosuid,size=64m -p 127.0.0.1:8002:8002 lena-audit-runtime
```

Dieser letzte Start prüft das eingeschränkte Profil **ohne normale fachliche Freitextsuche**. Für das erfolgreich geprüfte Textprofil werden zusätzlich folgende Prozessvariablen in den Container übergeben, beispielsweise per `-e NAME` aus einer sicher gesetzten Hostumgebung:

```text
REWRITE_PROVIDER=blablador
BLABLADOR_BASE_URL=https://api.blablador.fz-juelich.de/v1
BLABLADOR_API_KEY=<eigener gültiger Zugang>
BLABLADOR_MODEL=alias-fast
BLABLADOR_MAX_TOKENS=4096
LLM_INTERPRETER_TIMEOUT_SECONDS=15
LLM_SELECTOR_TIMEOUT_SECONDS=30
LLM_FORMULATOR_TIMEOUT_SECONDS=30
LLM_REQUEST_BUDGET_SECONDS=45
```

Die sicheren Dockerflags für deaktivierte lokale Envdateien, Autosync und Interaktionslogging bleiben wirksam. **Dieses Textprofil ist keine vollständige Speech-Konfiguration:** Das aktuelle Image erbt daraus ein nicht funktionierendes TTS-Defaultziel; siehe F-03. Die Seite und Textsuche funktionieren dennoch. Modellverfügbarkeit und Laufzeiten können sich ändern; der neue Smoke war ein einzelner erfolgreicher Aufruf, kein Zuverlässigkeitsversprechen.
